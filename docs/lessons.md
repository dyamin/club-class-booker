# Lessons: problems we hit, and the rule that stops them from coming back

Each row is a real problem from building and testing this program. The rule is already in the code or in the way we work. When you meet a new problem, add a row, and add a fake mode and a test that reproduces it.

## Checks before you touch the real app

1. Is the Mac unlocked and the app in front? (`ax dump` or a screenshot)
2. Does the screen show what you think it shows? (one look, one decision)
3. Is the action **counted** (a login code, a booking)? Then run it once and keep the result.
4. Can the action be undone? If not, ask first.
